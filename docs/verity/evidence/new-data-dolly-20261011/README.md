# Databricks Dolly 15k source audit — 11 October 2026

**Status: QUARANTINED_REVIEW_ONLY.** No Azaeron training, dataset admission, benchmark claim, or production promotion is authorized. This source is distinct from the owner's rejected OASST1 proposal and the previously examined HelpSteer source. It has a stronger publisher-side commercial training statement, but has not passed Azaeron's row-level or owner gates.

The [Databricks dataset card](https://huggingface.co/datasets/databricks/databricks-dolly-15k) names Databricks, Inc. as owner, declares CC BY-SA 3.0, explicitly permits commercial use, and lists training LLMs as a supported use. The [publisher blog](https://www.databricks.com/blog/2023/04/12/dolly-first-open-commercially-viable-instruction-tuned-llm) says more than 5,000 employees authored records in March–April 2023 and that responses were to be original, without web or generative-model copying except Wikipedia reference passages for certain tasks. This is stronger public contributor provenance than the OASST1 packet; neither source publishes per-row author identity, employment/work-product grants, or independent row-level copyright clearance. The [CC BY-SA 3.0 terms](https://creativecommons.org/licenses/by-sa/3.0/legalcode) require attribution and share-alike for covered uses, and the practical application to a model and its distribution needs an accountable decision. A publisher license cannot grant rights it does not hold.

The exact Hugging Face dataset revision is `bdd27f4d94b9c1f951818a7da7fd7aeea5dbff1a`. Its README and payload SHA-256 hashes match the prior publisher metadata and [audit-summary.json](audit-summary.json). The 13 MB payload was fetched solely into `/tmp/azaeron-dolly-audit-20261011`. [audit.py](audit.py) verifies the pinned hashes and emits only counts, source line locators, per-row SHA-256 digests and flags to [row-hashes.jsonl](row-hashes.jsonl); no raw third-party text is committed.

All **15,011 rows** have the four expected string fields. The categories comprise 3,742 open QA, 2,191 general QA, 2,136 classification, 1,773 closed QA, 1,766 brainstorming, 1,506 information extraction, 1,188 summarization and **709 creative writing**. **10,544 rows have no context field content**; **4,467 rows contain publisher-described Wikipedia context** (the closed QA, extraction and summarization categories). The payload contains no per-row author, source page, revision, or document ID. The context-free population therefore offers a more promising, but still unapproved, instruction subset. It does not cover editing, humanisation, voice preservation, or MeaningLock pairs.

Automated review found **97 distinct rows** with email, URL, phone-like or long-number patterns (28 context-free, 69 context-backed); these are review leads, not verified private data. Among context-backed rows, 52 responses match the normalized context and 201 have a long response excerpt within it. There are 154 groups containing 372 rows with duplicate normalized instruction-plus-context keys. These findings require row-level disposition and leakage-aware source grouping; the script makes no legal or factual-quality judgment.

The existing production reader requires five isolated splits, row source/author/document lineage, completed copyright and PII review, a human rights review, and a confirmed project-owner decision. Dolly supplies one published train file with no author IDs or Wikipedia page/revision attribution. We have not fabricated those fields, exported training splits, or treated the publisher's general privacy statement as clearance. The next accountable review must determine whether the context-free subset can be supported by contributor grants and privacy/copyright inspection, and separately whether every Wikipedia-backed row can satisfy source attribution and share-alike obligations. Independent quality testing and broader task-complete data remain necessary.
