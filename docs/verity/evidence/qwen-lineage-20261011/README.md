# Qwen MLX lineage check — 11 October 2026

**Result: publisher snapshot and local bytes verified; exact conversion lineage remains BLOCKED.** This is non-training evidence for the rejected `Qwen/Qwen3-4B-MLX-4bit` DEV_ONLY candidate. It does not alter the owner rejection, admit a base model, or authorize training or commercial serving.

Run `python3 docs/verity/evidence/qwen-lineage-20261011/verify.py --online --output docs/verity/evidence/qwen-lineage-20261011/verification.json` from the repository root. The script hashes the existing local bundle, checks the safetensors header and index without loading tensor payloads, fetches only bounded publisher metadata and small text assets, and never downloads checkpoint weights. Offline rechecks omit `--online`.

The pinned [Qwen MLX snapshot](https://huggingface.co/Qwen/Qwen3-4B-MLX-4bit/tree/52a5ab34fa604bc8af6d3ce0cac0cab10b7eb495) identifies Apache-2.0 and publishes the same 2,137,326,367-byte safetensors SHA-256 (`e56a94b846a2dce7d1cc154ce58b9cfc4b8d99e8ffb74bfe256a265f4cbc7fb9`) and tokenizer SHA-256 (`aeb13307a71acd8fe81861d94ad54ab689df773318809eed3cbe794b4492dae4`) as the local cache. All seven local bundle files match the recorded hashes. The pinned [MLX license file](https://huggingface.co/Qwen/Qwen3-4B-MLX-4bit/blob/52a5ab34fa604bc8af6d3ce0cac0cab10b7eb495/LICENSE) and [later source license file](https://huggingface.co/Qwen/Qwen3-4B/blob/1cfa9a7208912126459214e8b04321603b3df60c/LICENSE) both have SHA-256 `832dd9e00a68dd83b3c3fb9f5588dad7dcf337a0db50f7d9483f310cd292e92e`. The checked MLX snapshot publishes no `NOTICE` file. This records publisher licensing evidence, not an independent legal conclusion.

The [Qwen3-4B source repository](https://huggingface.co/Qwen/Qwen3-4B/tree/531c80e289d6cff3a7cd8c0db8110231d23a6f7a) revision `531c80e289d6cff3a7cd8c0db8110231d23a6f7a` was its latest before the MLX repository's initial weight upload on 23 May 2025. It is a **compatible source candidate**, not an identified conversion parent. Its published tokenizer object digest and the fetched `tokenizer_config.json`, `merges.txt`, and `vocab.json` hashes match the MLX bundle. Core architecture fields match. The publisher's three source shard SHA-256 values are captured in [verification.json](verification.json); source weight bytes were not downloaded or independently hashed. The later [source revision with LICENSE](https://huggingface.co/Qwen/Qwen3-4B/tree/1cfa9a7208912126459214e8b04321603b3df60c) advertises the same source shard object hashes.

The configurations are **not identical**: among other changes, `max_position_embeddings` is 40,960 in the compatible source and 65,536 in MLX, `max_window_layers` is 36 versus 28, and the MLX file adds 4-bit/group-128 quantization fields. The [pinned MLX model card](https://huggingface.co/Qwen/Qwen3-4B-MLX-4bit/blob/52a5ab34fa604bc8af6d3ce0cac0cab10b7eb495/README.md) does not name an exact unquantized source revision, conversion command/tool revision, or signed conversion manifest. Matching tokenizer/architecture and chronology cannot prove that the local quantized weights came from the candidate source shards. Reproducing a conversion later would not, by itself, prove the publisher's historical conversion inputs.

**Admission consequence:** preserve Qwen third-party attribution and the existing DEV_ONLY boundary. A new packet would need publisher conversion provenance or an independently controlled conversion from a fully hashed, rights-reviewed source bundle, followed by a new hash-bound owner review and all model release gates. The rejected packet's hash is not reusable as approval.
