# Controlled Qwen3-4B MLX conversion — unadmitted candidate

**Result:** A new third-party Qwen conversion was executed offline on the 16 GiB Mac. It is neither an Azaeron-trained checkpoint nor an approved base model. The owner’s rejection of the earlier Qwen MLX/OASST1 packet remains in force. No training, registry change, or public deployment occurred.

The inference-relevant `Qwen/Qwen3-4B` source assets were downloaded at immutable revision `1cfa9a7208912126459214e8b04321603b3df60c`. [Source verification](source-verification.json) hashes all 12 local files; all three weight shards, the tokenizer, and the Apache-2.0 file match the pinned publisher evidence. The [publisher file list](publisher-file-list.json) contains no `NOTICE` file. This verifies bytes and published license text; it is not a legal admission decision. Source and output weights stay in ignored local `.verity-local/` directories, separate from the original DEV_ONLY MLX bundle.

The [offline conversion runner](run.py) first verifies the source hashes and requires at least 20 GiB free. It invokes installed `mlx-lm==0.32.0` with 4-bit affine quantization, group size 128, remote code disabled, and Hub/Transformers offline. Exact installed package versions are in the [environment inventory](environment.lock.txt); wheel hashes are not locked. The runner copies the exact source `LICENSE` and `tokenizer.json` into the output; MLX-LM's `save_pretrained` otherwise reserializes tokenizer JSON, changing its byte hash. The first execution completed weight conversion but failed this strict tokenizer-byte check. Its [log](conversion.log) is retained. We then copied the exact verified source tokenizer into the new output and reran [the verifier](verify.py); the runner now performs that normalization automatically. The converter-emitted tokenizer digest is recorded in the [manifest](conversion-verification.json). Repeated conversion determinism has not been measured.

The new quantized `model.safetensors` SHA-256 is `55467c6157306f2a4463e9d149b0ed2552943f187778cc67d02e5bef4735773d`; the prior MLX bundle is `e56a94b846a2dce7d1cc154ce58b9cfc4b8d99e8ffb74bfe256a265f4cbc7fb9`. [Tensor comparison](tensor-comparison.json) found the same 904 tensor names, shapes and dtypes, but only 74 identical tensor payloads. A short offline generation smoke returned `ready` from both bundles; the [three-prompt behavior check](behavior-comparison.json) produced different wording on all three prompts. These checks establish compatibility of the new conversion, **not** that the publisher's older MLX bundle used this exact source or conversion procedure, and they are not a product-quality benchmark. The controlled smoke reported 2.242 GB peak MLX memory; one short response cannot establish sustained throughput or production latency. No external inference API was called.

The controlled source and conversion are a **new candidate for accountable review**. Commercial base admission, any training on this base, independent quality comparison, and production serving remain blocked until the project owner approves an exact hash-bound packet after rights and technical review. Dataset rights, human review, independent specialist checkpoints, and release evidence remain separate gates.
